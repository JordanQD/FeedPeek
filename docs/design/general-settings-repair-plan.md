- 来源按标识合并，恢复文件中的配置，保留文件之外的已有来源；不删除历史、已读和稍后再看数据。

- 数据库中的来源与通知配置使用事务恢复；系统开机启动不能保证恢复成功时，明确提示部分完成，不能显示无条件成功。

- 验证版本校验、非法输入不写入、来源/通知恢复、关闭开关与删除状态保留、旧格式兼容，并构建应用。

## 2. 保留弹窗状态（已完成）

开启“保留弹窗位置”后，保存上次页面和直播区域展开状态，关闭弹窗或切页销毁 UI 后，在新页面中恢复。状态以本机 LocalSettings 的枚举和布尔值持久化，不缓存页面 UI 树或会话；应用重启后也可恢复。

- 首次开启且没有记录时，使用“默认打开页面”和“正在直播”的默认显示方式。
- 关闭保留开关时清除两项记录，每次打开按默认设置复位；重新开启不会恢复关闭前的旧记录。
- 切离关注页前保存直播状态，关闭时即使停留在历史或稍后再看页，也不会丢失之前的直播展开状态。
- 显式修改“正在直播”的显示方式后清除旧展开记录；旧页面销毁时不能覆盖新设置。隐藏模式始终隐藏直播区域。
- 无效或缺失的保存值回退到默认设置。尚未真正打开的弹窗不因取消打开而写入页面记录。
- 配置导入导出仍保存保留开关和默认选项；上次交互页面与展开状态仅属于本机，不加入可迁移配置。导入关闭开关或不同直播显示方式时，同样清理旧状态。
- 自动验证不启动应用；下方人工验收覆盖真实托盘开关与页面重建。

验证：Debug x64 构建 **0 警告、0 错误**，差异空白检查通过。未启动应用、未写入当前用户的面板状态；真实交互效果待人工验收。

后续修正：关注页构造时只应用直播展开状态，尚未读取本地条目和直播内容时不能显示“还没有更新”。打开流程先读取并呈现当前页的本地缓存，再刷新来源内容和直播列表；移除重复打开激活，避免缓存读取排在网络刷新之后。仍沿用持久层缓存，不保留页面 UI。

直播缓存补齐：将上次成功获取的直播 DTO（名称、头像地址、直播链接等）写入本机 `FeedPeek/PanelLiveCache`，关闭弹窗、切页或重启后先读取缓存，再查询最新直播状态。按启用的插件、订阅和当前来源筛选读取；账号、插件版本或订阅地址/配置变化时旧缓存不匹配。完整成功结果替换缓存，完整空结果清除下播项；部分结果保留未观察到的旧项，失败/取消不清空。删除来源时清理其缓存。缓存不参与通知基线或配置导入导出。

直播布局核对：更新条目内容左右间距均为 `ListView` 内边距 8 + 条目内边距 12，即 20 DIP。直播滚动区原来仅有左边距 12，实际左右为 20/8 DIP；现改为左右边距均为 12，使滚动视口与更新条目内容均为 20/20 DIP。头像卡片内部自身的居中留白不计入区域间距；物理像素、滚动条与视觉对齐由人工截图验收。

展开按钮对齐：用户截图中，按钮背景约宽 404 像素，而下方原生 `ListViewItem` 背景约宽 396 像素；条目容器占用宽度与其背景宽度不同。按钮两侧设置 4 DIP 外边距、内部改为 `Padding="8,8"`，使背景按条目背景内缩，同时保持文字/箭头总偏移仍为 12 DIP；圆角复用 `ListViewItemCornerRadius`，最小高度保持 32 DIP。直播滚动区继续对齐条目内容边界。最终悬停边界仍需用户在更新后的应用截图中复核。

直播缓存验证：临时目录中的缓存重建、完整空结果、部分结果合并、首次不完整空结果、上下文隔离、取消、损坏文件与来源清理相关 **7 项测试通过**；Debug x64 构建 **0 警告、0 错误**，XAML 与差异检查通过。未读取或写入真实用户的直播缓存。首次升级后需成功获取一次直播数据才会建立缓存。

## 5. 人工验收

- 在测试配置中完成导出、修改选项、导入，检查来源、作者范围和通知开关。
- 导入旧文件、空对象、错误版本和损坏 JSON；失败后原配置不变。
- 系统拒绝开机启动时应提示部分完成。
- 提示条与来源安装提示外观、关闭及自动消失行为一致，隐藏后没有额外留白。
- 后续验证开机启动、重复启动、弹窗状态保留、语言和多显示器高度限制。
- 弹窗状态：开启保留开关，停留在历史或稍后再看，关闭后重新打开以及退出应用再启动，均应恢复对应页面。
- 直播状态：在关注页手动折叠/展开直播区，切到其他页再回到关注页，以及关闭后重新打开，状态应一致（需要至少一个正在直播的来源）。
- 关闭保留开关后，应恢复默认页面和默认直播状态；再开启不恢复已清除的旧状态。
- 保留开关开启时修改直播默认显示为展开、折叠或隐藏，重新打开应按新设置显示；旧弹窗关闭不能覆盖这个选择。
- 分别使用简体与繁体界面检查通用页，确认来源筛选标题、说明和无障碍名称已本地化；窄窗口下说明可完整换行，卡片之间间距一致。
- 已有缓存时重新打开弹窗，应先显示缓存，再更新内容，期间不能闪现“还没有更新”；真正没有更新且没有可见直播内容时才显示空状态。分别检查保留开关开启与关闭、历史页和稍后再看页，以及加载中关闭弹窗。
- 首次成功获取直播后关闭并重开弹窗、切页返回或重启应用，应先显示直播缓存；查询失败保留旧卡片，完整确认下播后移除。检查来源筛选、停用插件、删除来源、换账号后不显示不适用的缓存。
- 直播滚动区左右边界应与更新条目文字/缩略图边界一致；截图测量需按当前 DPI 换算，检查左右滚动时的裁切与滚动条。

真实来源、登录和系统启动状态由人工验收；自动验证使用临时数据库，不写当前用户配置。
